Goal

Add Mercari and Facebook Marketplace as automated-scan Sources alongside eBay, so the app can find candidate PC-part listings on both without the operator checking either site by hand. Neither platform has a public listings API, so both connectors drive a real headless/headed browser (Playwright) instead of a plain HTTP client — Mercari to pass its Cloudflare bot check, Facebook Marketplace to carry a real logged-in session on a dedicated secondary account. Craigslist and OfferUp are deliberately out of scope this round (see Assumptions).

Requirements

  • 1The app can run an automated Mercari scan for a Source: one or more configured search-query strings and an optional max-price ceiling, mirroring eBay's existing queries/maxPrice config shape. Each found item becomes a candidate Listing with title, asking price, listing photos, and a listing URL, deduplicated against Listings already imported for that Source exactly the way eBay-sourced candidates are deduplicated today. When a max price is configured, an item priced exactly at the ceiling is included and one priced $0.01 above it is excluded, proven as two explicit test cases (not inferred from Mercari's own search API, which may not honor the filter server-side).
  • 2Each newly-imported Mercari candidate gets a full description fetched from its own item detail page (not just the search-result summary), the same one-extra-call-per-new-candidate shape eBay's connector already uses — a failed detail fetch still imports the Listing, just without a description, logged at Warn (mirrors eBay's existing failure handling exactly).
  • 3The app can run an automated Facebook Marketplace scan for a Source, authenticated as a dedicated secondary Facebook account (never the operator's primary account — the user's own risk-mitigation choice): configured search-query strings, an optional location, an optional search radius, and an optional max-price ceiling. Each found item becomes a candidate Listing the same way as Requirement 1, with the same exact-boundary max-price behavior.
  • 4Each newly-imported Facebook Marketplace candidate gets a full description fetched from its own listing detail page, the same shape as Requirement 2.
  • 5A one-time, interactive command-line script lets the operator log into the dedicated Facebook account in a real, visible (non-headless) browser window — so any checkpoint/2FA challenge can be solved by a human — and persists that logged-in session to local disk for reuse by every later scan. No Facebook password is ever typed into a config file or an environment variable, and no scan re-authenticates from scratch.
  • 6When a Facebook Marketplace scan is attempted with no persisted session, or the persisted session has clearly expired (the scan lands on a login/checkpoint page instead of search results), it fails with one clear, actionable error naming the login script to re-run — never a silent zero-result scan that looks identical to "nothing matched."
  • 7The Sources UI (create/edit form, inline validation, round-trip on save, "Scan now" button) works for platformType mercari and facebook_marketplace exactly the way it already works for ebay today — a new connector-config editor per platform, with the same inline-validation-before-submit behavior the eBay editor already has.
