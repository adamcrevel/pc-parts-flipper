T6 Prototype — Non-working badge + per-part "Working status" control

Every element below reuses the real markup/classes from ebay-scan-badge.tsx, ai-suggested-badge.tsx, listings-queue-table.tsx, listing-form.tsx, expected-parts-editor.tsx, and button.tsx. The two genuinely new pieces are (1) a read-only NonWorkingBadge pill, amber instead of EbayScanBadge's emerald or AiSuggestedBadge's violet, and (2) a per-row Working / Not working segmented control that only appears on an Expected Parts row when its Listing is itself flagged non-working.

Dashed boxes like this one are prototype annotations only — not part of the real app's UI. Everything else (badges, table, form, buttons, inputs, borders, spacing) is the shipped component styling. Click things — the control below is live.

Piece 2 — per-part "Working status" control (live, click it)

Rendered inside each Expected Parts row's trigger (expected-parts-editor.tsx), next to the existing "Est. value" field — only when the Listing itself is flagged non-working. On an ordinary Listing this control doesn't render at all (see the toggle below). Toggling it doesn't just relabel the row: it clears the price field back to blank, the same "undecided" state priceSource: undefined already uses — ready for either the $1 auto-assign (Not working) or real research (Working) on the next save.
